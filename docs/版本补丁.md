# 版本补丁 pak（手机端）

> 现象：「一直显示版本错误」，是**游戏里**报的，不是面板报的。
> 根因：服务器下发的版本白名单是写死的常量，和 pak 实际写进去的版本号对不上。

## 一、机制

游戏客户端启动后会问服务器要 `server_options`，其中 `versions` 是**允许登录的版本白名单**。
客户端拿**自己的版本号**去这张表里找 —— 找不到就弹「版本错误」，登录就卡住。

客户端从哪读自己的版本号？从 `kards/Config/DefaultGame.ini` 里的 `ProjectVersion=`。
版本补丁 pak 就是一个覆盖这个 ini 的补丁包（UE 只加载 `_P` 结尾的 pak）：

```
assets/version.pak                          模板（12346 字节）
  └─ 运行时提取到 files/data/version.pak     （已存在则不覆盖，可手动替换）
       └─ 进游戏前写到游戏 Paks 目录           version_P.pak
            files/UnrealGame/kards/Engine/Content/Paks/version_P.pak
```

改写是**等长替换**：`ProjectVersion=` 后面的值按容量右填空格，pak 字节数不变
（pak 里有偏移表，长度一变整个包就废）。模板的容量是 **17**，原值 `KLink 29452.29452`
正好 17 个字符。

## 二、原来的 bug

`KardsHttpHandler.clientVersions()` 里的白名单是硬编码的：

```java
return new String[]{ "Kards 1.47", ..., VersionPakManager.DEFAULT_VERSION };
```

它只用 `DEFAULT_VERSION`（`KLink 29452.29452`）兜底，**完全不看你实际写进 pak 的值**。
于是：

- 你在「版本补丁」页填了任何自定义版本号 → pak 写的是你的值 → 白名单里没有 → 版本错误；
- 你的模板如果是别的版本号（不是 `KLink 29452.29452`）→ 同样不在白名单 → 版本错误；
- 而且 pak 已经装进游戏目录了，**每次启动都会被重新写一遍**，所以「一直」报，重启无用。

这是个典型的「设置能存、实际不生效」问题。

## 三、现在的做法

白名单改成**按客户端实际会读到的值**来算：

| 来源 | 说明 |
|---|---|
| 已装进游戏的 `version_P.pak` | 最准 —— 客户端真正会读到的就是它 |
| `pak_version.txt`（面板保存值） | 用户填的那个 |
| `version.pak` 模板原值 | 本地模式原样复制时写出去的就是它 |
| `DEFAULT_VERSION` 常量 | 兜底 |

每个值都加**两种形式**：去掉首尾空白的，和原样的。因为版本号短于容量时 pak 里是
`1.54.26471       `（带 7 个空格），客户端如果连空格一起报上来，只有原文能匹配。

白名单只表示"允许哪些版本"，放宽没有任何副作用。

## 四、模板不再是用户自己塞

桌面端是把模板当嵌入资源（`KLink.Server.csproj` 的
`<EmbeddedResource Include="Assets\kards-server\*.pak" />`）打包的。
手机端原先只在 `assets/version.pak` 找，而仓库里**根本没有这个文件** ——
等于新装用户永远「模板不存在」。现在已把桌面端那份模板原样打进
`source/assets/version.pak`（SHA256 与桌面端一致）。

提取逻辑是"存在则不覆盖"，所以老用户设备上已有的模板不会被替换。

## 五、怎么自查

面板 →「版本补丁」页，现在会多显示两行：

```
游戏内 pak 版本: 1.54.26471
版本白名单: 含该版本（共 15 项）
```

如果显示「不含 …→ 进游戏会报版本错误」，那就是白名单没跟上，红色标出来。

`GET /admin/pak/status` 也把 `output_version` / `output_exists` / `versions` 一起返回了。

## 六、验证

`temp/versioncheck`（不参与构建、不进 APK）用**真实的** `VersionPakManager`
和仓库里真实的 `version.pak` 跑：

- 本地模式原样复制：与模板**逐字节一致**，字节数不变；
- 改写版本：除版本号那 17 个字节外**没有任何字节变化**，字节数不变；
- 短版本号右填空格，`trim` 后等于目标值（这就是白名单要放行两种形式的原因）；
- 超长 / 非 ASCII 直接报错，且**报错不会破坏已生成的包**；
- `outputVersion()` / `savedVersion()` / `templateVersion()` 都能被服务器读到。

最后一次结果：**全部通过**。
