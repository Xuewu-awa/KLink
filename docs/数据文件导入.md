# 数据文件导入（library.json 等）

> 解决的问题：卡牌库 / 卡组代码表动不动几百上千条，在界面上一条一条录入不现实。
> 现在选一份整 JSON 文件就能导入，先出报告再落盘。

## 一、在哪用

KLink 面板 → 左侧「卡牌ID」→ 顶部 **导入数据文件**。

（面板从管理后台右下角的「控制面板」按钮进入。卡牌ID 管理器本来就只在面板里，
导入功能跟它放在一起。）

## 二、能导入什么

| 目标 | 文件 | 语义 |
|---|---|---|
| 卡牌库 | `library.json` | 结构化**合并 / 替换**，缺 `id` 自动回填 |
| 卡组代码 | `deck_code_ids.json` | 结构化**合并 / 替换** |
| 卡牌目录 | `cards-from-fmodel.json` | 整文件替换 |
| 商店配置 | `store.json` | 整文件替换 |
| 物品 | `items.json` | 整文件替换 |

**目标可以自动识别**：先看文件名，认不出来就看内容形态（裸数组 / `cards` 数组 /
`card` 映射 / `alwaysFeatured` …），都认不出来会明确报「认不出这是什么数据文件，
请手动选择导入目标」，不会瞎猜。

## 三、两步走，先看报告再落盘

1. 选文件 → 服务端只做预演（`apply=false`）：**不改内存、不写盘**，返回一份报告；
2. 报告里能看到「现有 N 条 → 导入后 M 条 / 新增 / 更新 / 未变 / 删除 /
   id 回填多少条 / 有多少无法回填 / 有哪些警告」；
3. 点「应用导入」才真正写入，写之前自动备份 `数据文件.yyyyMMdd_HHmmss.bak`，
   写完立即生效（清缓存，不用重启服务器）。

导入方式两种：

- **合并**：文件里的条目覆盖同名项，文件里没有的现有条目保留；
- **替换**：文件即全部，现有条目全部丢弃，条数/顺序/重复项都按文件来。

## 四、`id` 自动回填（这次的重点）

客户端导出的 `library.json` 有时**不带 `id`**（改用 `player_id`），而 `id` 是
卡牌ID管理器做匹配、删除、一致性检查的主键 —— 缺了就全变 0：

- 「按 id 删除」会**误删**（所有卡 id 都是 0，全命中）；
- 一致性检查**全量报错**。

导入时会按 `deck_code_ids.json` 的「卡牌名 → ID」反查回填，报告里如实写出
回填了多少条、多少条查不到（查不到的置 0）。反向也一样：导入 `deck_code_ids.json`
时缺 `ID` 的条目会按 `library.json` 反查。

## 五、未知字段会被保留

客户端导出的文件可能带 `player_id`、`new_cards` 之类的顶层字段，以及每条卡牌上的
`player_id`。手机端用不到，但用户拿这份文件去别处用的时候得还在 —— 保存时原样写回，
不做裁剪。（此前 `saveAll` 只写 `{"cards":[...]}`，会把这些字段丢掉。）

`library.json` 保存后 `cards` 永远在第一个键，方便跟客户端导出的原文对比。

## 六、实现位置

| 文件 | 作用 |
|---|---|
| `DataImportService.java` | 目标识别、路径白名单、整文件替换、报告拼装 |
| `CardIdManager.java` | `importLibrary` / `importDecks`（合并/替换/回填/差异统计） |
| `KardsHttpHandler.java` | `POST /admin/import`（本机免 token，非本机需 admin_token） |
| `assets/index.html` + `js/app.js` | 按钮、导入弹窗、报告渲染 |
| `KLinkBridge.onDataFilePicked` | 选文件 → 复制到缓存临时目录 → 通知前端 |
| `MainActivity.pickDataFile` | 系统文件选择器（不限定 MIME，见下） |

### 几个踩过的坑

- **大文件不能走 JS 桥**：卡牌目录 1.3MB，塞进 `evaluateJavascript` 会顶到 Binder
  传输上限。所以原生只把**文件路径**交给前端，内容由服务端自己读。
- **Android 10+ 给的是 `content://` URI**，服务端读不了 → 原生先复制到
  `cacheDir/import-spool/`，服务端**只允许读这个目录**（canonical 路径前缀校验，
  否则就成了任意路径读取的洞）。
- **文件选择器不要限定 MIME**：不少文件管理器把 `.json` 报成
  `application/octet-stream`，限定 `application/json` 会导致文件选不中，所以用通配类型。
